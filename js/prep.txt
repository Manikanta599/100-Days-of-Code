What do you mean by single-threaded?
It means JavaScript executes one piece of code at a time using a single call stack. However, asynchronous operations are handled efficiently through the Event Loop.


Is JavaScript interpreted or compiled?

JavaScript is neither purely interpreted nor purely compiled. because Modern JavaScript engines like V8 use Just-In-Time (JIT) compilation.
The engine first parses the code, compiles it into bytecode, and then frequently executed code is optimized into machine code for better performance.

Why is typeof null equal to "object"?
typeof null returns "object" because of a historical bug in the original JavaScript implementation.
Early JavaScript used type tags to identify values, and null was represented internally with a zero value that matched the object type tag.
This behavior became part of the language, and changing it now would break existing code, so it has been preserved for backward compatibility.
Although typeof null is "object", null is actually a primitive value. To check for null, use value === null.

What are variables?
A variable is a named container for storing data in memory. 
It allows a program to save values, retrieve them later, and update them when needed.
In modern JavaScript, we typically use let for values that may change and const for values that should not be reassigned.
Variables can store different data types such as numbers, strings, booleans, objects, arrays, and functions.

Difference between var, let, and const.
Interview-ready answer (with TDZ)

var, let, and const are all used to declare variables in JavaScript.

var is function-scoped, can be redeclared and reassigned, and is hoisted with an initial value of undefined, so it can be accessed before its declaration (though this can cause bugs).
let is block-scoped, cannot be redeclared in the same scope, but can be reassigned. It is also hoisted, but it remains in the Temporal Dead Zone (TDZ) from the start of the block until its declaration is executed. Accessing it during the TDZ throws a ReferenceError.
const is also block-scoped and hoisted with TDZ, but it cannot be reassigned after initialization. It must be initialized when declared. For objects and arrays, the reference cannot change, but their contents can still be modified.

In modern JavaScript, use const by default, use let when the value needs to change, and avoid var in new code.

One-line explanation of TDZ (commonly asked)

Temporal Dead Zone (TDZ) is the period between entering a block and the point where a let or const variable is declared. During this period, the variable exists but cannot be accessed, and attempting to do so results in a ReferenceError.

Example:

console.log(a); // undefined
var a = 10;

console.log(b); // ❌ ReferenceError (TDZ)
let b = 20;

console.log(c); // ❌ ReferenceError (TDZ)
const c = 30;

What is variable shadowing?
Variable shadowing is a situation where a variable declared in an inner scope has the same name as a variable in an outer scope.
The inner variable temporarily hides, or shadows, the outer variable within that scope.
JavaScript always looks for variables in the current scope first, then moves outward
Shadowing is valid with let, const, and var when the scopes don't conflict.
However, illegal shadowing occurs when a var declaration attempts to shadow an outer let or const in the same function/global scope, resulting in a SyntaxError.

illegal shadowing:
❌ Not Allowed
let a = 10;

{
    var a = 20;
}

let is block-scoped.
var is function-scoped.
The var declaration leaks outside the block into the same function/global scope, causing a conflict.

What is hoisting: 

Hoisting is JavaScript's behavior of moving declarations to the top of their scope during the memory creation phase before execution begins. Only declarations are hoisted, not initializations. var is initialized with undefined, so it can be accessed before its declaration. let and const are also hoisted, but they remain in the Temporal Dead Zone until their declaration executes, so accessing them early throws a ReferenceError. Function declarations are fully hoisted, but function expressions and arrow functions are not.

What is strict mode?

# What is Strict Mode? (Simple Interview Notes)

## Definition

**Strict Mode** is a special mode in JavaScript that **helps you write safer and cleaner code by catching common mistakes and preventing bad practices.**

To enable it, add this line at the top of your file or function:

```javascript
"use strict";
```

---

# Example

Without Strict Mode:

```javascript
name = "John"; // No var, let, or const
console.log(name);
```

✅ Output:

```text
John
```

JavaScript automatically creates a global variable (bad practice).

---

With Strict Mode:

```javascript
"use strict";

name = "John";
```

❌ Output:

```text
ReferenceError: name is not defined
```

Reason: Variables must be declared using `let`, `const`, or `var`.

---

# Why Use Strict Mode?

* ✅ Catches common coding mistakes.
* ✅ Prevents accidental global variables.
* ✅ Makes code more secure.
* ✅ Makes debugging easier.
* ✅ Encourages modern JavaScript practices.

---

# Common Rules in Strict Mode

### 1. Variables must be declared

❌ Without strict mode:

```javascript
x = 10;
```

✅ With strict mode:

```javascript
"use strict";

x = 10; // ReferenceError
```

---

### 2. Duplicate parameter names are not allowed

❌

```javascript
"use strict";

function add(a, a) {
    return a;
}
```

Output:

```text
SyntaxError
```

---

### 3. Cannot delete variables or functions

```javascript
"use strict";

let x = 10;

delete x;
```

Output:

```text
SyntaxError
```

---

### 4. `this` inside a normal function

Without strict mode:

```javascript
function show() {
    console.log(this);
}

show();
```

Output:

```text
Window (Browser)
```

With strict mode:

```javascript
"use strict";

function show() {
    console.log(this);
}

show();
```

Output:

```text
undefined
```

# Where to Use Strict Mode?

### Entire File

```javascript

// All code is in strict mode
```

### Specific Function

```javascript

    "use strict";

    // Only this function is in strict mode

```

Example:

```javascript

```

No need to write:

```javascript

```

What is type coercion?

**Type coercion is JavaScript's automatic conversion of one data type into another when performing operations. For example, "5" + 2 results in "52" because the number is converted to a string, while "5" - 2 results in 3 because the string is converted to a number. The == operator performs type coercion before comparing values, whereas === compares both value and type without any conversion. For predictable code, it's recommended to use ===.`


What is the difference between == and ===?

Why does [] == false return true?
[] == false

↓
false → 0

[] → ""

"" → 0

0 == 0

↓
true

more examples:
[] == false      // true
[] == 0          // true
[] == ""         // true

false == 0       // true
"" == 0          // true

[] == false returns true because the == operator performs type coercion. First, false is converted to 0. Then the empty array [] is converted to an empty string "", and the empty string is converted to 0. Finally, JavaScript compares 0 == 0, which is true. Using === avoids these automatic conversions and returns false because the types are different.

=============================================================================================================

null == undefined :

null == undefined returns true because JavaScript defines a special rule for the loose equality (==) operator: null and undefined are considered equal only to each other. No type coercion is performed in this case. However, null === undefined returns false because strict equality checks both value and type, and null and undefined are different types.

NaN == NaN :
NaN stands for Not-a-Number.

It represents the result of an invalid mathematical operation.

Example:
console.log(0 / 0);      // NaN
console.log(Number("Hi"));// NaN
console.log(Math.sqrt(-1)); // NaN

This is a special rule in JavaScript (and IEEE 754 floating-point standard).
NaN is never equal to any value, including itself.
So:
NaN == NaN     // false
NaN === NaN    // false

JavaScript treats NaN as an unknown or invalid numeric value. Since its exact value is unknown, it cannot be considered equal to anything—not even another NaN.

Difference between Object.is() and ===. 
Both === and Object.is() compare values without type coercion. The main differences are in two special cases. === considers NaN not equal to itself and treats +0 and -0 as equal. Object.is() considers NaN equal to NaN and distinguishes between +0 and -0. For most comparisons, use ===. Use Object.is() only when you need these special comparison behaviors.

In JavaScript, every value is either truthy or falsy when evaluated in a boolean context. Falsy values are false, 0, -0, 0n, "", null, undefined, and NaN. Every other value is truthy, including empty arrays ([]) and empty objects ({}). JavaScript automatically converts these values to true or false in conditions such as if statements.

What are short-circuit operators?
Short-circuit operators stop evaluating expressions as soon as the result is known. The && operator returns the first falsy value or the last value if all are truthy. The || operator returns the first truthy value or the last value if all are falsy. The ?? operator returns the right-hand value only when the left-hand value is null or undefined. These operators are commonly used for conditional logic and providing default values.
